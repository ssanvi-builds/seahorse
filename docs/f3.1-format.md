# Seahorse Episode Format (F3.1)

The on-disk memory format of Seahorse. A Seahorse vault is a directory of
markdown files where each file is one **episode** — a single atomic unit of
memory for an LLM agent.

The format is designed around three goals:

1. **Human-readable and portable** — an episode is markdown with a YAML
   frontmatter block. You can read, edit, and diff it with any markdown tool,
   including Obsidian.
2. **Point-in-time reproducible** — every episode carries two time axes, so the
   knowledge base can be reconstructed as it was at any past moment.
3. **Append-only** — content is never overwritten in place. Corrections create a
   new episode that supersedes the previous one; history is preserved.

---

## 1. File structure

An episode is a `.md` file:

```text
---
<frontmatter YAML>
---
<body markdown>
```

- The **frontmatter** is a single YAML block between two `---` delimiter lines.
  It is the machine contract.
- The **body** is everything after the closing `---`, preserved byte-for-byte
  (never re-parsed, never stripped). It is first-class: the agent and the human
  see the same note.

## 2. Fields

### 2.1 Required fields

Every episode must carry these four fields. A parser treats a missing required
field as a hard error, never a silent default.

| Field | Type | Semantics |
|---|---|---|
| `id` | string (UUIDv7) | Unique episode identifier. UUIDv7 is time-ordered and collision-safe. Immutable. |
| `created_at` | datetime (ISO-8601 `Z`) | System time the episode was recorded. Immutable. |
| `schema_version` | string (semver) | Version of the format this note conforms to. The current version is `0.1.0`. |
| `provenance` | mapping | Who wrote the episode and how (see [§2.3](#23-provenance)). |

### 2.2 Optional fields

| Field | Type | Semantics |
|---|---|---|
| `valid_at` | datetime \| null | Real-world time from which the fact is true. `null` means "always true" / not applicable. |
| `invalid_at` | datetime \| null | Real-world time until which the fact was true. `null` means still true. Setting it once (`null → now`) is a soft-delete. This is the **only** mutable timestamp. |
| `expired_at` | datetime \| null | System time at which the episode decays (forgetting). Reserved for a later release; must be `null` in the current one. Distinct from `invalid_at`: decay (forgetting) is not invalidation (contradiction). |
| `supersedes` | string (UUIDv7) \| null | `id` of the episode this one replaces. The anchor for the supersession chain. |
| `supersedes_reason` | string \| null | Why this episode supersedes the previous one. See the enum in [§3](#3-enums). |
| `cognitive_type` | string \| null | Cognitive class of the episode. See the enum in [§3](#3-enums). |
| `source_type` | string \| null | Origin of the content. See the enum in [§3](#3-enums). |
| `title` | string \| null | Human title (not unique). |
| `summary` | string \| null | Short summary (≤ 280 chars). |
| `tags` | list[string] | Free-form categorization tags. Not relationships. |

Two derived fields — `subject` and `fact_id` — are computed by the engine from
the body (title / first heading) and are **not** stored in the frontmatter.

### 2.3 Provenance

`provenance` is a nested mapping that records who wrote the episode and how, for
audit and multi-agent isolation:

| Field | Type | Semantics |
|---|---|---|
| `agent_id` | string | Identifier of the agent that wrote the episode. |
| `session_id` | string | Session identifier for the ingestion. |
| `source_type` | string | Origin: `agent`, `human`, `importer`, or `system`. |
| `extraction_mode` | string | How the frontmatter was produced. See the enum in [§3](#3-enums). |
| `model_used` | string \| null | Model that generated the frontmatter (when `extraction_mode=llm`). |
| `tool` | string \| null | Tool or plugin that originated the episode. |
| `prompt_hash` | string \| null | SHA-256 (hex) of the prompt that produced the episode. |
| `confidence` | float \| null | Extraction confidence in `[0.0, 1.0]`. |
| `importer_vendor` | string \| null | Vendor source when `source_type=importer`. |
| `importer_loss` | mapping \| null | Documented data loss from an import. |

### 2.4 Vendor extensions (`x-*`)

Any field with an `x-` prefix (top-level or inside `provenance`) is a vendor
extension, in the style of HTTP headers / RFC 8288:

- The core **ignores** `x-*` fields for business logic.
- The core **preserves** them through a round-trip.
- Namespacing convention: `x-<vendor>-<field>`, e.g. `x-mem0-op`.
- The router for the cognitive dual-mode only reads `cognitive_type` — no `x-*`
  field can influence it.

## 4. Bi-temporal model

Every episode is recorded on two time axes:

- **`valid_at` / `invalid_at`** — the *real-world* axis: when the fact was true
  in the world.
- **`created_at` / `expired_at`** — the *system* axis: when the episode entered
  the knowledge base and when it decayed.

The two axes answer three distinct questions:

| Question | Fields |
|---|---|
| "When was this fact true in the world?" | `valid_at` / `invalid_at` |
| "When did the system learn it?" | `created_at` |
| "When did the system forget it?" | `expired_at` |

A single `updated_at` collapses these irrecoverably — point-in-time reasoning
requires the separation.

### Invariants

- **Immutability**: `valid_at`, `created_at`, and `expired_at` are immutable
  once written. `invalid_at` is the only mutable timestamp, set exactly once
  (`null → now`) at invalidation.
- **Append-only**: there is no in-place update. Correcting content creates a new
  episode with `supersedes=<previous id>`. The old episode is invalidated, never
  erased.
- **Monotonicity**: `valid_at <= invalid_at` and `created_at <= expired_at`.
- **Current-state predicate**: an episode is currently true when `invalid_at IS
  NULL` and `expired_at IS NULL`.
- **Lifecycle**:
  - `remember` creates an active episode (`valid_at <= now`, `invalid_at=null`).
  - A future `valid_at` puts the episode in a *pending-ingest* state until its
    time arrives.
  - `improve` invalidates the old episode and creates a new one that supersedes it.
  - `forget` soft-deletes by setting `invalid_at` once. History is preserved.
  - `revalidate` (a human reversing an invalidation) creates a new episode — it
    never rewrites `invalid_at` back to `null` on the invalidated version.

## 5. Canonical example

A realistic episode note:

```markdown
---
id: 01972e3a-4f8b-7c2d-9e1a-3b5f0c8a2d67
created_at: 2026-06-15T10:04:33Z
schema_version: 0.1.0
provenance:
  agent_id: seahorse/migrator
  session_id: sess_01J9X3K4M2N7P9QZ
  source_type: human
  extraction_mode: skip
valid_at: 2026-06-15T10:00:00Z
cognitive_type: semantic
title: "Markdown as a first-class memory format"
tags: [decision, architecture, memory-format]
---

# Markdown as a first-class memory format

## Decision

Seahorse stores agent memory as markdown notes with bi-temporal YAML frontmatter.
```

Notes on the example:

- `valid_at` (10:00Z) differs from `created_at` (10:04:33Z): the decision was
  made at 10:00 and recorded about four minutes later. This separation is the
  value of the bi-temporal model.
- `extraction_mode: skip` means the frontmatter was written directly, without an
  LLM extraction step.
- Null-valued optional fields (`invalid_at`, `expired_at`, `supersedes`, …) are
  omitted on disk — absent means the field is null.
- The body is preserved byte-for-byte; the frontmatter never rewrites it.

## 6. Serialization

- **YAML engine**: `ruamel.yaml` in round-trip mode, so comments, key order,
  quote style, block scalars, and anchors/aliases survive a rewrite.
- **Timestamps**: ISO-8601 UTC with a trailing `Z` (e.g.
  `2026-06-15T10:04:33Z`). Naive datetimes (no timezone) are rejected on read.
  The original zone offset is deliberately canonicalized to UTC — a portable
  format cannot depend on the writer's timezone.
- **Null policy**: fields with `null` values are not written to disk in the
  current release. A later release may switch to writing explicit `null`.
- **Write format**: `---\n{frontmatter}\n---\n{body}`. The frontmatter is
  written with canonical indentation (mapping 2, sequence 4); the body is
  written verbatim.
- **Atomic writes**: files are written to a temporary file and atomically
  renamed, so a watcher (e.g. Obsidian) never sees a half-written note.

## 7. Versioning

`schema_version` is strict semver (`MAJOR.MINOR.PATCH`):

| Change | Version bump |
|---|---|
| New optional field, new reserved enum value, new recognized `x-*` | MINOR |
| New required field, type change, semantic change, removed enum value | MAJOR |
| Validator fix without schema change | PATCH |

Current version: `0.1.0`.

Forward compatibility: a reader of an older version treats an unknown optional
field like an `x-*` extension — it preserves it on round-trip and ignores it in
logic. A major version bump is a hard contract boundary: reading a note with a
higher `MAJOR` fails loudly rather than silently.

## 8. Extensibility

- `x-*` fields are the extension channel without a version bump. Vendors add
  fields without breaking the core; the core preserves them on round-trip.
- A field can be promoted from `x-*` to a core field via a MINOR version bump.
- Reserved namespaces are declared for planned features (e.g. decay
  parameters) so vendors do not reuse them for something else.
